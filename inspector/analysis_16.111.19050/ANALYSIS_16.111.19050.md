# Статический анализ BLACK RUSSIA 16.111.19050 — структура игрока/машины и исходящая сеть

**Дата:** 25.10.2026 (Europe/Moscow)  
**Объект:** `libblackrussia-client-16.111.19050.so`, ELF AArch64, 36 296 864 байта  
**SHA-256:** `44e5b7f5e22a2fa7fb16268bf043d25f1feeb1d600dd6b56feb3b43dd236f1fd`  
**Версия:** библиотека из обновлённого APK 16.111.19050 (Android patch 1580). Адреса ниже — VA внутри ELF до ASLR; не файловые смещения и не runtime-адреса после загрузки.

## Краткий результат

В новой `.so` напрямую подтверждены 14 статических вызовов `RakClient::Send` (11 уникальных packet ID, включая 4 вызова ID 27) и 62 RPC callsite-кандидата строгой выборки (18 ID). Наиболее насыщенный RPC-кандидат — 413, 43 callsite в строгой выборке. Отдельно сохранено 119 записей широкой RPC-эвристики; это записи с повторами и часть из них не подтверждена полным путём сериализации, поэтому они не объявляются 119 уникальными сообщениями.

Проверены числовые форматы сериализаторов, размеры тел и связи `serializer → Send`. Получена новая проверка для актуального бинаря: таблица PlayerPool индексируется шагом 8 байт, предел ID 1503; VehiclePool проходит 2000 слотов по 8 байт. Перепроверены поля локального/удалённого игрока и сетевого транспорта, используемые в актуальных отправителях и применителях. Семантика отдельных полей неясна — в таблицах это отмечено явно, а не переименовано по догадке.

Основной режим для большинства перечисленных игровых пакетов: `priority=1`, `reliability=1`, `channel=0`. ### Охват и исключённые ложные кандидаты

Проверенный raw-send список содержит 17 кандидатов: 14 настоящих send callsite из таблицы выше и три вызова в `0x1933A7C` (`0x1933C5C`, `0x1933D50`, `0x1933D74`), которые **не** обращаются к global RakClient/BitStream path и являются generic virtual callbacks другого объекта; они исключены из списка сетевых отправок. Три дополнительных Send-site вне главного игрового диапазона — `0x1470300`, `0x150C660`, `0x156025C` — проверены: все используют RakClient, сериализуют ID 27 и потому включены в каталог, а не отнесены к GUI/IPC по одному лишь адресу функции.

«Все» здесь означает все callsite, найденные поиском виртуального RakClient `Send` и прослеженные до `BitStream` в анализируемой `.so`; оно не означает полную динамическую трассу всех веток во время игрового сеанса. Условные отправки могут не происходить в конкретной сессии.

## 2. Исходящие RPC

RPC отправляются отдельным виртуальным методом RakClient/RakPeer (слот vtable `+0xB0`), а не `Send` `+0x38`. Эвристика ранжировала вызовы по комбинации vtable-slot, подготовки BitStream, константы ID и параметров приоритета/надёжности.

| Уровень выборки | Callsite | Уникальных ID | ID |
|---|---:|---:|---|
| Строгая выборка по полному локальному call pattern (кандидат, всё ещё требует flow-by-flow проверки) | 62 | 18 | 314, 320, 324, 342, 355, 356, 357, 361, 371, 374, 378, 403, 413, 414, 423, 436, 437, 441 |
| Широкая аргументная эвристика, включает строгие и дополнительные шумные совпадения | 119 записей (с дублями по ID/функциям) | 26 | 67, 69, 314, 320, 324, 342, 355, 356, 357, 361, 367, 371, 374, 378, 382, 396, 403, 409, 413, 414, 423, 436, 437, 441, 451, 454 |

RPC **413** имеет 43 callsite в строгой выборке и 89 сырых записей в широкой; значительная часть повторов — разные участки обширной sync/serialization логики, а не 89 уникальных RPC. Остальные IDs — числовые ID кандидатов, не имена функций протокола. Без подтверждённой таблицы receiver-side dispatch/фактического вызова на каждом сайте нельзя выдавать всю эту эвристику за доказанный список активных отправок.

Для воспроизводимой фильтрации включены оба JSON-артефакта `outbound_rpc_callsites_strict.json` и `outbound_rpc_callsites_argshape.json`; файл `outbound_rpc_callsites_by_id.csv` даёт дедуплицированную сводку по ID и VA. Метод поиска намеренно не использует эвристику «где-то рядом `mov w1`», так как она ранее показала ложные совпадения.

## 6. Что приложено и границы уверенности

- `manifest.json` фиксирует ELF-секции/размер/SHA-256; адреса и смещения отделены.
- `raw_send_slot38_candidates.json` — 17 кандидатов, включая три отсеянных generic callbacks.
- `outbound_rpc_callsites_strict.json` и `outbound_rpc_callsites_argshape.json` — строгая и широкая RPC выборки; ни одна не маскируется под полностью доказанный runtime перечень.
- `outbound_packet_catalog.csv`, `outbound_rpc_ids_by_id.csv`, `structure_offsets_16.111.19050.csv` — машиночитаемые каталоги.
- Полная APK в ZIP не включалась: по запросу упакована именно извлечённая библиотека и материалы её анализа. Публично известный Play/RuStore rollout/patch индекс использовался лишь для выбора актуального APK; семантика пакетов выводилась из самой новой `.so`, не из прежней сборки.

Сетевые значения, которые не имеют независимого reader-side подтверждения, специально помечены как «не установлено». Для абсолютно полного динамического списка того, что реально отправляется на каждом состоянии игры, понадобится capture/Frida-трассировка именно 16.111.19050; статический поиск не может показать неисполненные ветви.
